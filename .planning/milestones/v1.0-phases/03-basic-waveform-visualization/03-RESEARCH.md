## Summary

Phase 3 adds a waveform visualization area between the metadata section (LayoutRenderer) and the control bar (ControlBarRenderer). The waveform is generated by bulk-decoding the audio data into PCM float samples using a separate BASS decode stream (independent of the playback stream), computing per-column peak amplitudes, and persisting the result to a temp-folder cache. Rendering uses GDI+ in the existing OnPaint/double-buffer pipeline.

The key architectural challenge is that waveform generation is expensive (seconds for long files) and must happen on a background thread with CancellationToken support for file-switch cancellation. The existing PreviewWindow layout must be extended to allocate a waveform zone above the control bar, pass waveform state to a new WaveformRenderer, and route mouse events to new waveform hit zones.

The playback integration is straightforward: the existing 250ms position timer already fires Invalidate; the waveform renderer just needs to read `_player.CurrentPositionSeconds` on each paint to draw the playhead.

**Primary recommendation:** Implement WaveformGenerator (background Thread + CancellationToken + separate BASS decode stream from pinned byte[]), WaveformCache (SHA-256 key, binary float[] file, size eviction), and WaveformRenderer (static GDI+ renderer following the ControlBarRenderer pattern already in the codebase).

### Pattern 1: Separate BASS Decode Stream for Waveform

**What:** Create a second `BassFlags.Decode | BassFlags.Float` stream from the same byte[] as the playback stream. Decode chunks using `Bass.ChannelGetData`. This is independent of the playback stream — seeking or playing the playback stream does not affect the decode stream.

**When to use:** Any time peak data for the full file is needed without disturbing active playback.

**How BASS decode works:**
- `Bass.CreateStream(ptr, 0, length, BassFlags.Decode | BassFlags.Float)` creates a stream that decodes but does not play
- For decode streams, `Bass.ChannelGetData` has no playback buffer limit — it decodes directly from source
- Return value of -1 means error; return value of 0 means no more data (end of stream)
- Float samples are in range [-1.0, +1.0] (may slightly exceed 1.0 for clipped content)
- Use `Math.Abs(sample)` to get peak amplitude; track max per column window

**Example:**
```csharp
// Source: BASS documentation (https://www.un4seen.com/doc/bass/BASS_ChannelGetData.html)
// and ManagedBass (https://managedbass.github.io/)

// Create a second decode stream from the same pinned byte[] already held by AudioPlayer
// NOTE: The byte[] must remain pinned (not GC'd) for the lifetime of this stream.
// WaveformGenerator pins its own copy OR takes a GCHandle from the caller.
int waveStream = Bass.CreateStream(
    dataPtr,      // IntPtr to pinned byte[] (same as playback stream source)
    0,
    dataLength,
    BassFlags.Decode | BassFlags.Float);

if (waveStream == 0)
    throw new InvalidOperationException($"Waveform decode stream failed: {Bass.LastError}");

long totalBytes = Bass.ChannelGetLength(waveStream);
double durationSec = Bass.ChannelBytes2Seconds(waveStream, totalBytes);

// Chunk size: ~4096 float samples per read (16384 bytes)
const int SamplesPerChunk = 4096;
float[] buffer = new float[SamplesPerChunk];
int samplesPerBar = /* compute from total samples and bar count */;
float barPeak = 0f;
int samplesInBar = 0;

while (!cancellationToken.IsCancellationRequested)
{
    int bytesRead = Bass.ChannelGetData(waveStream, buffer, buffer.Length * sizeof(float));
    if (bytesRead <= 0) break; // 0 = end of stream, -1 = error

    int floatsRead = bytesRead / sizeof(float);
    for (int i = 0; i < floatsRead; i++)
    {
        float abs = Math.Abs(buffer[i]);
        if (abs > barPeak) barPeak = abs;
        samplesInBar++;
        if (samplesInBar >= samplesPerBar)
        {
            peaks.Add(Math.Min(1f, barPeak));
            barPeak = 0f;
            samplesInBar = 0;
            // Progressive reveal: notify UI after each bar
        }
    }
}

Bass.StreamFree(waveStream);
```

### Pattern 2: WaveformRenderer — Static Renderer Following ControlBarRenderer

**What:** A static class that receives all state needed to render (peaks[], currentPosition, duration, hoveredX, isDragging, dragPosition, dpiScale) and draws to a Graphics context. Matches the existing ControlBarRenderer pattern exactly.

**When to use:** Called from PreviewWindow.OnPaint for the waveform rectangle.

**Key GDI+ operations:**
- `LinearGradientBrush(top, bottom, darkBlue, brightCyan)` — vertical gradient per bar
- `GraphicsPath.AddArc` at top of each bar for rounded top (same as DrawRoundedRect already in ControlBarRenderer)
- Playhead: `g.DrawLine(whitePen, x, top, x, bottom)` + small downward triangle at top using `g.FillPolygon`
- Dimming played bars: draw bars to left of playhead with alpha-reduced color (e.g., 60% opacity via `Color.FromArgb(alpha, r, g, b)`)
- Hover guide line: `g.DrawLine(guidePen, mouseX, top, mouseX, bottom)` — only when hovering

**Bar width formula (Claude's discretion):**
```csharp
// Adaptive bar count: target 2px gap between bars
// Example for 400px wide waveform:
// barCount = waveformWidth / (barWidth + gap)
// Minimum 1px bar, 1px gap → max density
// Use integer arithmetic to ensure whole-pixel bars

int gap = Math.Max(1, (int)(1.5f * dpiScale));        // 1-2px gap (DPI scaled)
int barCount = Math.Max(10, waveformWidth / (3 + gap)); // Start with ~3px bars
int barWidth = Math.Max(1, (waveformWidth - gap * (barCount - 1)) / barCount);
// Recompute barCount after barWidth to ensure fit:
barCount = (waveformWidth + gap) / (barWidth + gap);
```

**Gradient color scheme (Claude's discretion):**
```csharp
// Light theme: dark navy (quiet) → bright cyan (loud) per bar
// Dark theme: same hues but brighter to pop on dark background
// Per-bar color based on amplitude:
Color BarColorFromAmplitude(float amplitude, bool isDark)
{
    // amplitude in [0,1]
    // dark navy = (10, 30, 80), bright cyan = (0, 200, 230)
    // dark theme: (20, 60, 140) → (0, 220, 255)
    float t = amplitude;
    Color low  = isDark ? Color.FromArgb(20, 60, 140)  : Color.FromArgb(10, 30, 80);

    return Color.FromArgb(
        (int)(low.R + (high.R - low.R) * t),
        (int)(low.G + (high.G - low.G) * t),
        (int)(low.B + (high.B - low.B) * t));
}
// Played bars (behind playhead): same color but at ~55% alpha
Color playedColor = Color.FromArgb(140, barColor.R, barColor.G, barColor.B);
```

### Pattern 3: WaveformCache — SHA-256 Key + Binary Float[] File

**What:** Cache computed peak arrays to temp folder. Key is SHA-256 of file content (hex string). Cache entry is a binary file: 4-byte int (bar count) + N x 4-byte floats. On startup or after generation, check total cache size and evict oldest files if over limit.

**Cache key scheme (Claude's discretion):**
```csharp
// Key: SHA-256 of audio byte[] → lowercase hex string
// File: %TEMP%\Audex\{sha256hex}.wf
// Format: [int32 barCount][float32 x barCount]

static string ComputeCacheKey(byte[] audioData)
{
    using var sha = SHA256.Create();
    byte[] hash = sha.ComputeHash(audioData);
    return BitConverter.ToString(hash).Replace("-", "").ToLowerInvariant();
}

static string GetCachePath(string key)
{
    string dir = Path.Combine(Path.GetTempPath(), "Audex");
    Directory.CreateDirectory(dir);
    return Path.Combine(dir, key + ".wf");
}

// Write:
static void WriteCache(string path, float[] peaks)
{
    using var fs = new FileStream(path, FileMode.Create, FileAccess.Write);
    using var bw = new BinaryWriter(fs);
    bw.Write(peaks.Length);
    foreach (float p in peaks) bw.Write(p);
}

// Read:
static float[]? ReadCache(string path)
{
    if (!File.Exists(path)) return null;
    using var fs = new FileStream(path, FileMode.Open, FileAccess.Read);
    using var br = new BinaryReader(fs);
    int count = br.ReadInt32();
    var peaks = new float[count];
    for (int i = 0; i < count; i++) peaks[i] = br.ReadSingle();
    return peaks;
}

// Eviction: sort cache files by LastWriteTime, remove oldest until total < 50MB
static void EvictIfNeeded(string cacheDir, long maxBytes = 50L * 1024 * 1024)
{
    var files = Directory.GetFiles(cacheDir, "*.wf")
        .Select(f => new FileInfo(f))
        .OrderBy(f => f.LastWriteTime)
        .ToList();
    long total = files.Sum(f => f.Length);
    foreach (var f in files)
    {
        if (total <= maxBytes) break;
        total -= f.Length;
        try { f.Delete(); } catch { }
    }
}
```

### Pattern 5: Progressive Reveal via Callback

**What:** WaveformGenerator reports newly computed bars via a callback/event. PreviewWindow accumulates bars in a float[] buffer and calls `Invalidate(waveformBounds)` on the STA thread after each bar (or batch of bars for performance).

**Generator callback contract:**

### Anti-Patterns to Avoid

- **Seeking the playback stream to decode waveform data:** Do not call `Bass.ChannelSetPosition` on the playback decode stream for waveform generation. This disrupts active playback and causes audible glitches. Always use a separate decode stream.
- **Drawing waveform bars as individual FillRectangle calls without SmoothingMode:** For rounded tops using GraphicsPath, enable AntiAlias before drawing. ControlBarRenderer already does this pattern correctly.
- **Invalidating the full UserControl every 250ms during playback:** Only invalidate the waveform rectangle (for playhead movement). The metadata area never changes during playback. Targeted `Invalidate(waveformBounds)` eliminates unnecessary metadata redraws.
- **Blocking the STA thread during waveform generation:** All BASS decode work must happen on a background Thread (IsBackground=true), never on the STA thread that owns the WinForms control.
- **Calling Control.Invoke from WaveformGenerator after the control is disposed:** Check `!_previewWindow.IsDisposed && _previewWindow.IsHandleCreated` before invoking.
- **Creating the waveform decode stream inside BassMix or as a mixer channel:** The waveform decode stream is a pure decode stream — do NOT add it to the mixer. Adding it to the mixer would route it to WASAPI output and produce audio.
- **Storing the GCHandle for the waveform decode stream in AudioPlayer:** WaveformGenerator manages its own pinned buffer and GCHandle independently.

## Common Pitfalls

### Pitfall 1: File-Switch Race Condition on Waveform Generation

**What goes wrong:** User opens file A, waveform generation starts on background thread. User immediately opens file B. Thread A is still running and calls Invoke to report bar data — it writes into _waveformPeaks which now belongs to file B's display context.

**Why it happens:** Background thread holds a reference to _waveformPeaks and the Invoke callback does not check if the generation request is still current.

**How to avoid:** Assign a generation ID (e.g., incrementing int) to each generation request. The Invoke callback checks: if the generation ID it was started with no longer matches `_currentGenerationId`, it discards the result silently.

**Warning signs:** Waveform from previous file briefly flickers into view on the new file's display.

### Pitfall 2: Waveform Stream Added to BassMix Mixer

**What goes wrong:** Developer calls `BassMix.MixerAddChannel` on the waveform decode stream, causing the raw decoded audio to be played through WASAPI.

**Why it happens:** Copy-paste from AudioPlayer.LoadFile which adds the stream to the mixer.

**How to avoid:** WaveformGenerator MUST NOT call BassMix at all. The waveform stream uses only `Bass.CreateStream + Bass.ChannelGetData + Bass.StreamFree`.

**Warning signs:** Distorted audio or double-playback of audio when waveform is generated.

### Pitfall 3: GCHandle Freed Before Bass.StreamFree

**What goes wrong:** If WaveformGenerator frees its pinned GCHandle before calling `Bass.StreamFree`, BASS holds a dangling pointer into the GC heap. Subsequent access causes memory corruption.

**Why it happens:** Natural disposal order (dispose managed resources first, then native).

**How to avoid:** Always call `Bass.StreamFree(waveStream)` BEFORE `gcHandle.Free()`. This is already established as a pattern in AudioPlayer (see "GCHandle freed AFTER Bass.StreamFree" in project memory).

**Warning signs:** Access violation exceptions in prevhost.exe, often appearing seconds after waveform generation.

### Pitfall 4: Bar Count Mismatch Between Generation and Render

**What goes wrong:** WaveformGenerator computes peaks at 400 bars (pane width at generation time). When the pane is resized, WaveformRenderer tries to render 600 bars but only has 400 peaks, causing array index out of bounds or stretched appearance.

**Why it happens:** Peak count is coupled to pane width at generation time.

**How to avoid:** Generate peaks at a fixed high resolution (e.g., 2000 peaks). At render time, downsample or upsample by averaging/selecting peaks to match the actual bar count. This also means the cache stores a canonical peak array independent of display width.

**Canonical peak count recommendation:** 2000 peaks per file. This gives ~1 bar per pixel at 2000px pane width (rare) and 5 peaks averaged per bar at 400px (common). Averaging groups of peaks produces visually accurate amplitude representation.

### Pitfall 5: Invalidating Full Control During Playback

**What goes wrong:** The position timer calls `Invalidate()` (no rectangle), causing the full UserControl to repaint including the metadata area. At 250ms intervals this is 4 full redraws per second of static content.

**Why it happens:** Easy to call `Invalidate()` without thinking about cost.

**How to avoid:** Store the waveform bounds as a field updated in OnPaint. The position timer calls `Invalidate(_waveformBounds)` only. The control bar already uses this pattern (see `Invalidate(controlBarBounds)` in OnPositionTimerTick).

**Warning signs:** CPU usage spikes during playback even when metadata is static.

### Pitfall 6: BASS Not Initialized on Waveform Background Thread

**What goes wrong:** WaveformGenerator calls `Bass.CreateStream` on a background thread. BASS was initialized on the STA thread. On some systems, BASS returns error BASS_ERROR_INIT.

**Why it happens:** BASS.Init with device 0 (NoSound) is COM-apartment agnostic in practice, but calling stream creation from an MTA thread after STA-thread init can occasionally fail on certain configurations.

**How to avoid:** Empirically, BASS NoSound device (device=0) is safe to call from any thread. However, add error checking and fall back to "Waveform unavailable" gracefully. The existing AudioPlayer already demonstrates that the WASAPI callback (an MTA thread) successfully calls `Bass.ChannelGetData` — the same operation WaveformGenerator needs.

**Warning signs:** WaveformGenerator immediately fails with `Bass.LastError = BASS_ERROR_INIT`.

### Pitfall 7: Hover Tooltip Positioned Outside Control Bounds

**What goes wrong:** Time tooltip drawn near cursor position extends beyond the right or left edge of the waveform control, getting clipped or appearing outside the window.

**Why it happens:** Tooltip X is simply `mouseX + offset` without bounds checking.

**How to avoid:** Clamp tooltip X to `Math.Max(waveformBounds.Left, Math.Min(waveformBounds.Right - tooltipWidth, mouseX + offset))`.

**Warning signs:** Tooltip text truncated at right edge of pane.

### Bulk Decode for Waveform Peaks

```csharp
// Source: BASS documentation (un4seen.com/doc/bass/BASS_ChannelGetData.html)
// and ManagedBass API (managedbass.github.io)

// Pin the file byte[] independently of the playback stream's pinned buffer
GCHandle handle = GCHandle.Alloc(audioBytes, GCHandleType.Pinned);
int waveStream = 0;
try
{
    waveStream = Bass.CreateStream(
        handle.AddrOfPinnedObject(), 0, audioBytes.Length,
        BassFlags.Decode | BassFlags.Float);

    if (waveStream == 0)
    {
        // Waveform unavailable — clean up and return
        handle.Free();
        return null;
    }

    long totalSamples = Bass.ChannelGetLength(waveStream) / sizeof(float);
    int targetBars = 2000; // canonical resolution
    int samplesPerBar = Math.Max(1, (int)(totalSamples / targetBars));

    var peaks = new List<float>(targetBars);
    float[] buf = new float[4096];
    float barMax = 0f;
    int samplesAccum = 0;

    while (!ct.IsCancellationRequested)
    {
        int bytesRead = Bass.ChannelGetData(waveStream, buf, buf.Length * 4);
        if (bytesRead <= 0) break;
        int floats = bytesRead / 4;
        for (int i = 0; i < floats; i++)
        {
            float v = Math.Abs(buf[i]);
            if (v > barMax) barMax = v;
            samplesAccum++;
            if (samplesAccum >= samplesPerBar)
            {
                peaks.Add(Math.Min(1f, barMax));
                barMax = 0f;
                samplesAccum = 0;
                onBarReady?.Invoke(peaks.Count - 1, peaks[^1]); // progressive reveal
            }
        }
    }

    return ct.IsCancellationRequested ? null : peaks.ToArray();
}
finally
{
    if (waveStream != 0) Bass.StreamFree(waveStream); // MUST be before handle.Free()
    handle.Free();
}
```

### Waveform Bar Rendering (GDI+)

```csharp
// Source: GDI+ System.Drawing API (docs.microsoft.com)
// Pattern follows ControlBarRenderer.DrawRoundedRect already in codebase

static void DrawWaveformBar(Graphics g, int barX, int barWidth,
    int centerY, int halfHeight, Color color, bool isRoundedTop)
{
    int topY = centerY - halfHeight;
    int rectHeight = halfHeight * 2;

    if (rectHeight < 1) rectHeight = 1;

    if (isRoundedTop && halfHeight >= 2)
    {
        int radius = Math.Min(barWidth / 2, 2); // small radius for dense bars
        // Top arc
        using var path = new GraphicsPath();
        path.AddArc(barX, topY, barWidth, radius * 2, 180, 180); // top rounded
        path.AddLine(barX + barWidth, topY + radius, barX + barWidth, centerY + halfHeight);
        path.AddLine(barX + barWidth, centerY + halfHeight, barX, centerY + halfHeight);
        // Bottom arc (mirrored)
        path.AddArc(barX, centerY + halfHeight - radius * 2, barWidth, radius * 2, 0, 180);
        path.CloseFigure();
        using var brush = new SolidBrush(color);
        g.FillPath(brush, path);
    }
    else
    {
        using var brush = new SolidBrush(color);
        g.FillRectangle(brush, barX, topY, barWidth, rectHeight);
    }
}
```

```csharp
private CancellationTokenSource? _waveCts;

void StartWaveformGeneration(byte[] audioData, AudioFileInfo info)
{
    _waveCts?.Cancel();
    _waveCts?.Dispose();
    _waveCts = new CancellationTokenSource();
    var ct = _waveCts.Token;
    int generationId = Interlocked.Increment(ref _generationId);

    var t = new Thread(() =>
    {
        float[]? peaks = WaveformGenerator.Generate(audioData, ct, OnBarReady);
        if (peaks == null || ct.IsCancellationRequested) return;
        InvokeOnUI(() =>
        {
            if (_currentGenerationId != generationId) return; // stale
            _waveformPeaks = peaks;
            Invalidate(_waveformBounds);
        });
    });
    t.IsBackground = true;
    t.Start();
}
```

```csharp
using System.Security.Cryptography;

static string ComputeCacheKey(byte[] data)
{
    using var sha = SHA256.Create();
    return BitConverter.ToString(sha.ComputeHash(data))
                       .Replace("-", "")
                       .ToLowerInvariant();
}
```

## Open Questions

1. **Multichannel (>2 channels) peak extraction**
   - What we know: BASS float decode stream interleaves channels (L, R, L, R... for stereo; L, R, C, LFE... for 5.1)
   - What's unclear: Should waveform peak use max across all channels, or average, or just channel 0?
   - Recommendation: Use `Math.Max` across all channels within each sample frame (most representative of perceptual loudness). Divide sample index by `info.Channels` to get frame number.

2. **Very short files (< 1 second)**
   - What we know: samplesPerBar could be 0 if totalSamples < targetBars
   - What's unclear: How to handle files shorter than 2000 samples
   - Recommendation: Clamp samplesPerBar to minimum 1; cap targetBars to `(int)totalSamples`. For extremely short files, show a few wide bars.

3. **Cache warm-up timing relative to playback start**
   - What we know: DoPreviewInternal calls AudioPlayer.LoadFile (which pins the byte[]), then UpdateContent. WaveformGenerator needs the same byte[] (or a copy).
   - What's unclear: Should WaveformGenerator get its own copy of the byte[] or take a pointer to the same pinned buffer?
   - Recommendation: Pass the `byte[]` reference (not a copy) to WaveformGenerator. WaveformGenerator creates its own GCHandle pin independently. The byte[] is kept alive in AudioPreviewHandler._fileData until Unload, which is after the waveform thread completes (or is cancelled).

4. **Waveform height when metadata area is very small (narrow pane)**
   - What we know: 40-50% of preview pane height allocated to waveform
   - What's unclear: What is the minimum useful waveform height?
   - Recommendation: Enforce minimum waveform height of 60px (DPI scaled). If the pane is too short to show waveform + control bar + any metadata, collapse metadata first (hide it), keeping waveform + control bar.
