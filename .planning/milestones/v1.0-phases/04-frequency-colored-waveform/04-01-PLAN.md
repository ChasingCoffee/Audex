**Create `FrequencyColorMapper.cs`** in `src/Audex/Audio/`:

A static class with these members:

**Constants (all named internal constants per locked decision):**
- `FftWindowSize = 2048` (named constant, tweakable but not user-facing)
- `BassLowHz = 20f`, `BassMidHz = 200f` (DJ-standard crossover, locked)
- `MidHighHz = 2500f`, `HighMaxHz = 16000f` (DJ-standard, locked)
- `EnergyThreshold = 0.008f` (below this, render neutral/gray, locked)

**Static methods:**
1. `FreqToBin(float hz, int sampleRate, int fftSize) -> int` — standard DSP formula: `(int)(hz * fftSize / sampleRate)`. Compute bin boundaries at runtime (NOT hardcoded) to handle 44100, 48000, 22050 Hz etc.

2. `BandRms(float[] fft, int start, int end) -> float` — sum of squared magnitudes (power weighting per research), divided by count, then sqrt. Skip bin 0 (DC). Use `Math.Max(1, start)` for start.

3. `Compute(float[] fft, int sampleRate, int fftSize, bool isDark) -> Color` — the main method:
   - Compute bin boundaries via FreqToBin for all 4 crossover frequencies
   - Call BandRms for bass, mids, highs
   - Sum total energy. If below EnergyThreshold, return neutral color (dark: `Color.FromArgb(60, 60, 65)`, light: `Color.FromArgb(180, 180, 185)`)
   - Compute ratios: bR = bass/total, mR = mids/total, hR = highs/total
   - Dark theme palette (muted/desaturated per locked decision, heat spectrum: bass=red/warm, mids=yellow-green, highs=blue/cool):
     ```
     r = (int)(195 * bR + 150 * mR + 35 * hR)
     g = (int)( 55 * bR + 170 * mR + 95 * hR)
     b = (int)( 35 * bR +  35 * mR + 190 * hR)
     ```
   - Light theme: multiply by ~0.75 for contrast on near-white background:
     ```
     r = (int)(145 * bR + 110 * mR + 25 * hR)
     g = (int)( 40 * bR + 125 * mR + 70 * hR)
     b = (int)( 25 * bR +  25 * mR + 140 * hR)
     ```
   - Clamp all to 0-255 and return `Color.FromArgb(r, g, b)`

4. `NeutralColor(bool isDark) -> Color` — returns the neutral gray for below-threshold bars.

5. `SmoothColors(Color[] colors) -> void` — 3-tap moving average (in-place, skip index 0 and last):
   - For i = 1 to length-2: average R, G, B of [i-1], [i], [i+1]
   - Process into a temp array first, then copy back (avoids cascading averaging artifacts)

**Extend `WaveformGenerator.cs`:**

Change the `Generate` method signature to return a tuple or result object. Add a new overload or modify the existing method:

`public static WaveformData? Generate(byte[] audioData, CancellationToken ct, Action<int, float>? onBarReady = null)`

Where `WaveformData` is a simple class/struct:
```csharp
public class WaveformData
{
    public float[] Peaks { get; set; }
    public Color[]? FrequencyColors { get; set; }
}
```

**Inside the decode loop**, after completing each bar's worth of PCM samples (after `peaks.Add(peakValue)`):
1. Call `Bass.ChannelGetData(waveStream, fftBuffer, (int)DataFlags.FFT2048)` — the FFT operates on the last decoded data, not advancing the stream
2. Get sample rate from `ChannelInfo` (already retrieved once before the loop — store `info.Frequency`)
3. If fftBytesRead > 0, call `FrequencyColorMapper.Compute(fftBuffer, sampleRate, FrequencyColorMapper.FftWindowSize, isDarkMode)` where `isDarkMode` is obtained from `ThemeHelper.IsSystemInDarkMode()` (call once before the loop, cache the result)
4. Store the color in `colors[barIndex]`
5. If FFT fails (bytesRead <= 0), use `FrequencyColorMapper.NeutralColor(isDark)`

After the main loop completes:
- Call `FrequencyColorMapper.SmoothColors(colors)` for the 3-tap neighbor smoothing (locked decision: smooth transitions between bars)
- Include colors in the returned WaveformData

**IMPORTANT:** The `fftBuffer` must be allocated once before the loop: `float[] fftBuffer = new float[FrequencyColorMapper.FftWindowSize / 2]` (1024 floats for FFT2048).

**IMPORTANT:** The `onBarReady` callback signature stays the same — it only reports peak progress. Colors are not reported progressively (they are assigned to WaveformData.FrequencyColors as a complete array after generation finishes — per research pitfall #6 about keeping colors and peaks in sync).

**IMPORTANT:** Add `using System.Drawing;` and `using Audex.UI;` (for ThemeHelper) to WaveformGenerator.cs imports.

**`WriteColorCache(string key, Color[] colors)`:**
- Build path: `Path.Combine(Path.GetTempPath(), CacheSubfolder, key + ColorCacheExtension)`
- Ensure cache directory exists (reuse GetCachePath pattern or call GetCachePath then swap extension)
- Write binary: version byte (1), then int32 count, then count x 3 bytes (R, G, B per color)

**`ReadColorCache(string key) -> Color[]?`:**
- Build path same way
- If file doesn't exist, return null
- Read version byte — if != ColorCacheVersion, delete file and return null (per pitfall #3 about cache format versioning)
- Read int32 count — sanity check (>0, <1_000_000)
- Read count x 3 bytes, construct `Color.FromArgb(r, g, b)` per entry
- Touch LastWriteTimeUtc for LRU ordering
- Return array, or null on any error

**Update `EvictIfNeeded`:** Currently only evicts `.wf` files. Change the glob pattern from `"*" + CacheExtension` to `"*.wf*"` so it catches both `.wf` and `.wfc` files, OR use two GetFiles calls and concatenate. The total size limit (50MB) should apply across both file types combined.
