    1. Create `src/Audex/Audio/AudioPlayer.cs`:
       This is the core audio engine. It manages BASS initialization, WASAPI output, stream lifecycle, and playback controls.

       **Class structure:**
       - Private fields: `_decodeStream` (int), `_pinnedBuffer` (GCHandle?), `_state` (AudioPlayerState), `_wasapiProc` (WasapiProcedure), `_endOfStreamFlag` (int, for Interlocked), `_isInitialized` (bool), `_totalDurationSeconds` (double)
       - Event: `EventHandler<AudioPlayerState> StateChanged` — fires when state transitions
       - Event: `EventHandler PlaybackEnded` — fires when track finishes (checked on UI timer, not from WASAPI proc)

       **Initialize() method (called once in AudioPreviewHandler constructor):**
       - Call `SetDllDirectory` to add the assembly's directory to the DLL search path (prevhost.exe runs from System32). Use P/Invoke: `[DllImport("kernel32.dll", SetLastError = true, CharSet = CharSet.Unicode)] static extern bool SetDllDirectory(string lpPathName);`
       - Get assembly directory: `Path.GetDirectoryName(typeof(AudioPlayer).Assembly.Location)`
       - Store the WasapiProcedure delegate in a field (`_wasapiProc = WasapiCallback`) to prevent GC collection
       - Call `Bass.Init(0)` — NoSound device (device index 0), required for WASAPI output path
       - Call `BassWasapi.Init(-1, 0, 0, WasapiInitFlags.Shared, 0f, 0f, _wasapiProc, IntPtr.Zero)` — default device, shared mode
       - Call `BassWasapi.Start()` — start WASAPI output (no-op until proc has data)
       - Set `_isInitialized = true`
       - If any step fails, set state to Error, log the specific BassError, return false
       - Anti-pattern: Do NOT use `Bass.Init(-1)` — that opens a real output device conflicting with WASAPI

       **LoadFile(byte[] data, string fileName) method (called per file):**
       - If currently playing/paused, call StopAndFreeStream() first
       - Set state to Loading
       - Pin the byte array: `_pinnedBuffer = GCHandle.Alloc(data, GCHandleType.Pinned)`
       - Create decode stream: `Bass.CreateStream(_pinnedBuffer.Value.AddrOfPinnedObject(), 0, data.Length, BassFlags.Decode | BassFlags.Float)`
       - MUST use both BassFlags.Decode (no direct output) AND BassFlags.Float (WASAPI expects float PCM)
       - If stream creation fails, free GCHandle, set state to Error, log Bass.LastError
       - Read technical metadata: `Bass.ChannelGetInfo(stream, out ChannelInfo info)` for Frequency (sample rate) and Channels
       - Read duration: `Bass.ChannelBytes2Seconds(stream, Bass.ChannelGetLength(stream))`
       - Store `_totalDurationSeconds`
       - Set state to Stopped (ready to play, position at start)
       - Reset `_endOfStreamFlag = 0`
       - Return AudioFileInfo-compatible metadata (sample rate, channels, duration). Note: bit depth should come from Phase 1 header parsers (BASS always reports 32-bit float for decode streams).

       **Play() method:**
       - If state is Stopped and stream position is at end, seek to 0 first
       - Set state to Playing
       - Reset `_endOfStreamFlag = 0` if seeking to start

       **Pause() method:**
       - If state is Playing, set state to Paused

       **Stop() method (per user decision: stop resets position to start):**
       - Set state to Stopped
       - Seek stream to position 0: `Bass.ChannelSetPosition(_decodeStream, 0)`

       **Seek(double seconds) method:**
       - `Bass.ChannelSetPosition(_decodeStream, Bass.ChannelSeconds2Bytes(_decodeStream, seconds))`

       **SetVolume(float volume) method (0.0 to 1.0):**
       - Use `BassWasapi.SetVolume(WasapiVolumeTypes.Session, volume)` — NOT Bass.ChannelSetAttribute
       - BASS channel volume does NOT work with WASAPI decode streams (research pitfall 7)

       **Properties:**
       - `CurrentPositionSeconds`: `Bass.ChannelBytes2Seconds(_decodeStream, Bass.ChannelGetPosition(_decodeStream))`
       - `TotalDurationSeconds`: stored from LoadFile
       - `State`: current AudioPlayerState

       **CheckEndOfStream() method (called from UI timer, not from WASAPI proc):**
       - `if (Interlocked.CompareExchange(ref _endOfStreamFlag, 0, 1) == 1)` — atomically check and reset
       - If true: state = Stopped, seek to 0, fire PlaybackEnded event
       - Per user decision: when track finishes, stop and reset position to start, button shows Play

       **WasapiCallback(IntPtr buffer, int length, IntPtr user) method:**
       - CRITICAL: This runs on WASAPI's high-priority audio thread. ONLY call `Bass.ChannelGetData` here. No UI calls, no stream free, no logging, no BASS functions other than ChannelGetData.
       - If `_decodeStream == 0` or `_state != AudioPlayerState.Playing`: return `length` (silence)
       - `int bytesRead = Bass.ChannelGetData(_decodeStream, buffer, length)`
       - If `bytesRead <= 0`: set `Interlocked.Exchange(ref _endOfStreamFlag, 1)`, return 0
       - Return bytesRead

       **StopAndFreeStream() private method:**
       - Set state to Idle
       - If `_decodeStream != 0`: `Bass.ChannelFree(_decodeStream)`, then set to 0
       - If `_pinnedBuffer.HasValue`: `_pinnedBuffer.Value.Free()`, then set to null
       - CRITICAL ordering: Free BASS stream BEFORE freeing GCHandle (research pitfall 2)

       **Shutdown() method (called from AudioPreviewHandler.Unload or disposal):**
       - Call StopAndFreeStream()
       - `BassWasapi.Stop()`, `BassWasapi.Free()`, `Bass.Free()`
       - Set `_isInitialized = false`

       - `WriteStream` throws `NotSupportedException`
       - `CloseStream(Stream stream)` calls `stream?.Dispose()`
