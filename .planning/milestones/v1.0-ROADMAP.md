# Roadmap: Audex

## Overview

Building a Windows Explorer preview handler for audio files requires establishing a stable COM foundation first, then layering audio capabilities. The journey starts with COM shell extension infrastructure, adds BASS audio playback and basic visualization, enhances with frequency-colored waveforms and extended format support, then finishes with BPM/key detection and configuration. Each phase delivers complete, verifiable user-facing capabilities while preventing architectural pitfalls that would require expensive rewrites.

## Phase Details

### Phase 1: COM Shell Extension Foundation
**Goal**: Preview handler appears in Windows Explorer when user selects audio file, with proper resource cleanup and low-integrity process compatibility
**Depends on**: Nothing (first phase)
**Requirements**: PREV-01, PREV-02, PREV-03, PREV-04, PREV-05
**Success Criteria** (what must be TRUE):
  1. User selects audio file in Explorer and preview pane appears with placeholder UI
  2. User selects different audio file and preview updates without locking previous file
  3. Preview handler runs correctly in Explorer's low-integrity process without permission errors
  4. Errors during preview loading are logged to AppData for debugging
  5. Preview pane closes cleanly without causing Explorer crashes or handle leaks
**Plans**: 3 plans

Plans:
- [ ] 01-01-PLAN.md — Project scaffold, COM interfaces, config, logging, path utilities
- [ ] 01-02-PLAN.md — COM preview handler core with lifecycle management and audio header parsers
- [ ] 01-03-PLAN.md — Preview window UI, theme support, registration, and end-to-end verification

### Phase 2: BASS Audio Integration
**Goal**: User can play audio files with playback controls and see basic file metadata
**Depends on**: Phase 1
**Requirements**: PLAY-01, PLAY-03, FMT-01, META-01, META-02
**Success Criteria** (what must be TRUE):
  1. User can click play button and hear audio through default WASAPI output
  2. User can pause, stop, and control volume independently of system volume
  3. Preview displays duration, sample rate, bit depth, channel count, and basic tags (title/artist/album)
  4. WAV, MP3, and FLAC files play correctly without crashes
  5. BASS audio resources are properly released when switching files (no handle leaks after 50+ file switches)
